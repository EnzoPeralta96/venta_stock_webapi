## 1. Flujo mejorado: Compra desde Lista de Precios

### Qué cambió
Antes había que navegar manualmente: Proveedor → volver → Compras → seleccionar lista. Ahora existe un atajo directo.

### Cómo funciona ahora
- En la página de detalle de una lista de precios (`/proveedores/:id/lista/:idLista`) hay un botón **"Realizar compra"** en el header (arriba a la derecha).
- Al hacer clic navega directamente al formulario de compra con la lista ya pre-seleccionada.
- Si el usuario cancela la compra, vuelve a la lista de precios (no al tab de compras).

### Archivos modificados
- `src/components/Proveedores/ListaDetailsPage.jsx` — botón "Realizar compra"
- `src/components/Proveedores/ProveedorDetailsPage.jsx` — detecta navegación con state, abre form automáticamente
- `src/components/Compras/CompraForm.jsx` — nueva prop `listaInicial` para pre-seleccionar lista

### Detalle técnico (CompraForm)
```jsx
<CompraForm
  proveedorInicial={proveedor}
  listaInicial={idListaParaCompra}  // ← nuevo prop
  ...
/>
```
Cuando `listaInicial` viene con un ID, el form espera a que carguen las listas del proveedor y auto-selecciona la que corresponde.

## 2. Códigos de barra — constraint ÚNICO restaurado

### Qué cambió
Se restauró el constraint `UNIQUE` en la tabla `codigo_barra` que había sido eliminado en una sesión anterior.

### Por qué
Dos productos distintos **no pueden tener el mismo código de barra**. La confusión era: "todos los martillos del mismo modelo tienen el mismo código en la góndola" — pero eso es porque son el mismo producto, no productos distintos.

### Migración aplicada
`RestoreBarcodUniqueConstraint` — ya aplicada en Railway. Incluye limpieza de duplicados existentes antes de crear el índice.

### Backend
- Nuevo error code: `ProductErrorCode.barcode_in_use` → "Uno o más códigos de barra ya están registrados en otro producto."
- `ProductServices.Create()` — valida barcodes antes de insertar
- `ProductServices.Update()` — valida solo los barcodes nuevos (no falla por los propios del producto)

## 3. Lista de Precios — rol definitivo: Catálogo Pasivo

### Decisión arquitectónica
La Lista de Precios es un **catálogo histórico de cotizaciones del proveedor**. No modifica productos nunca.

**Para qué sirve:**
- Registrar qué cobra cada proveedor por cada producto
- Referencia visual al armar una compra (los precios se pre-cargan pero son editables)
- Base de datos para BI futuro: comparar qué proveedor conviene para un producto, medir inflación interanual por proveedor

**Lo que NO hace:**
- Nunca actualiza `Producto.Costo`, `Producto.Precio` ni `Producto.PorcentajeGanancia`

### Cambios en backend
`AddItemsBulkAsync` y `AddItemAsync` en `ListaPrecioItemServices` — solo hacen upsert en `ProductoListaprecioProveedor`. Sin lógica de producto.

## 4. Nueva feature: Actualización Masiva de Precios (en módulo Productos)

### Por qué se movió
Actualizar precios es una tarea del catálogo del negocio, no de un proveedor específico. Un "Pintura Alba 1L" puede comprarse a varios proveedores — remarcar precios por inflación es independiente de quién lo vende.

### Dónde vive ahora
Menú → Productos → botón **"Actualizar Precios"** → `/productos/actualizar-precios`

### Dos modos de uso

#### Modo Manual
1. Buscás productos por nombre o marca
2. Los agregás a una tabla de staging
3. Editás el Costo Neto, IVA% y Margen% de cada uno
4. El sistema muestra en tiempo real el **Precio de Venta resultante**
5. Hacés clic en "Actualizar" → se graban los cambios
6. El modal muestra un resumen **antes / después** por producto

#### Modo Excel
1. Descargás la plantilla con todos los productos activos pre-cargados (CodigoBarra, Nombre, CostoActual, MargenActual)
2. Completás/modificás los costos en Excel
3. Subís el archivo
4. El sistema actualiza todos los productos que encuentra por código de barra

**Formato de la plantilla (fijo):**
| CodigoBarra | NombreProducto | NuevoCosto | MargenGanancia |
|---|---|---|---|
| 7790001234 | Pintura Alba 1L | 850.00 | 30 |

> ⚠️ La plantilla tiene formato fijo del sistema. No es para subir el Excel crudo del proveedor (cada proveedor manda formatos distintos).

### Endpoints nuevos en backend

| Método | Ruta | Descripción |
|---|---|---|
| `GET` | `/Product/plantilla-precios` | Descarga Excel plantilla |
| `POST` | `/Product/actualizar-masivo/manual` | Actualización por UI |
| `POST` | `/Product/actualizar-masivo/excel` | Actualización por archivo |

Permiso requerido: `PERM:PROD_UPDATE`

### Lógica de cálculo
```
costoConIva = costoNeto × (1 + ivaPorcentaje / 100)
producto.Costo = costoConIva
Si margen fue ingresado → producto.PorcentajeGanancia = margen
producto.Precio = producto.Costo × (1 + producto.PorcentajeGanancia / 100)
```
Si no se ingresa margen → se preserva el margen actual del producto.

### Auditoría
Cada actualización masiva queda registrada en el log de auditoría con usuario, fecha, y valores anteriores/nuevos de cada producto.
